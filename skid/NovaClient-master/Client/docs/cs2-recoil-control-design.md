# Recoil Control 设计文档

版本：1.0 · 2026-09-22 · CS2 Build 14181。

本文确定模块行为、数据来源、接入边界和验收标准。原生实现已接入，实际入口、算法与验证边界见 [实施记录](cs2-recoil-control-implementation.md)。尚未在游戏中注入或实射验收；下文保留设计阶段证据及验收标准。

## 1. 设计结论

新增 `Combat → General → Recoil Control`，默认关闭。它根据本地玩家当前有效后坐力连续补偿水平和垂直角度，保留用户鼠标输入，画面视角与实际射击方向使用一致的输入链路。

采用**实时有效后坐力反馈**。每把枪的资源数据用于识别型号、类别、射击模式及状态校验；补偿量来自游戏按时间计算的有效 AimPunch，不把资源中的 RecoilMagnitude 直接当作角度，也不靠固定时长的鼠标下拉曲线。

第一版不提供没有第二种实现的 Mode 选择。保留四个参数：Horizontal、Vertical、Start Bullet、Smooth。复用现有模块、配置、绑定和 ClickGUI 控件，不新增 HUD，不复制公共 UI。

## 3. IDA 分析决定的行为

本次 client.dll SHA256 为 `A0C195F0B6EC00915EF08C548200A010EBBE7982D3A4BC468CAD939B67C8C4E3`，与本机安装文件一致。以下均为该文件的 RVA。

| 证据位置 | 已确认行为 | 对设计的影响 |
| --- | --- | --- |
| `0x7A9B80` | 根据武器编号和种子，为两个模式分别生成 64 项方向/幅度表；全自动有连续项混合与初始幅度处理 | 枪械存在自身后坐力规律，但这张表不等于实际屏幕角度轨迹 |
| `0x7ABD80` | 缓存按物品编号索引；读取使用模式及 `index & 63` | 不按实体名称或简单 elapsed-time 识别当前后坐力项 |
| `0x7A9E80` | 单独生成多弹丸相关数据 | 后坐力与随机散布不是同一件事；RCS 不承诺消除散布 |
| `0x7FCEE0 → 0x835850` | 从当前模式取得方向/幅度，在时间上下文中给 predictable 角速度加入射击冲量；另有模式间幅度混合分支 | 以实际本地预测射击和原版有效结果为准，不硬编码每把枪的冲量 |
| `0x7FA230 → 0x8268B0` | `LandPunchAngleYaw` 路径也修改 predictable 基础角度 | predictable 不是“纯开枪后坐力”的同义词 |
| `0x82B500` | 在调用者给定时间分别计算 predictable、unpredictable 分量并相加 | 射击时间与求值时间必须一致 |
| `0x7E8600` | 射击数据准备路径调用上述合成求值，缩放参数为 true，再合入方向 | 第一版补偿对象选为射击链路使用的有效 AimPunch；不能只取一个未经求值的基础字段 |
| `0x827220` | 时间衰减、缓存、插值和可选倍增 | 不在返回值上再次无条件乘 2；不从 Present 任意调用会维护缓存的服务 |
| `0x82C8F0` | 可单独读取经过求值的 predictable 分量，用于相关显示路径 | 屏幕辅助显示使用的分量与射击方向求值路径要区分 |
| `0xCB1890 → 0xCA8920` | 构建命令角度历史并管理攻击历史索引，复制每个样本的角度和时间到 protobuf | 补偿应在历史样本形成前进入同一输入链，不能只改最终一份角度 |
| `0x7D67C0` | 原生 VData 构造初始化 | 补齐资源省略字段的初始化证据，避免把省略项当成未知数值 0 |

从取表、施加冲量到时间求值的链路已经可以解释为何静态 RecoilMagnitude 无法直接用于压枪。后坐力数值还会随射击模式、当前索引、时间和已有角速度变化。

第一版明确采用**有效射击角度反馈**：有射击活动时，跟踪实际射击链路使用的合成 AimPunch。因此若射击期间落地或受到其他影响 AimPunch 的事件，可能同时补偿该有效角度变化。它不是“仅移除枪械来源、保留其他所有来源”的分离器，也不是关闭模型动画或全局 ViewPunch。无射击时不因落地或受伤自行压枪。

## 4. 用户操作与参数

入口：Combat → General → Recoil Control。默认关闭、默认不绑定快捷键；支持现有 Toggle/Hold 绑定。开启后自动识别当前枪械，手动射击时生效。

| 显示名称 | 范围 / 步长 | 默认 | 明确定义 |
| --- | --- | ---: | --- |
| Horizontal | 0–100%，1% | 100% | Yaw 补偿比例，0 表示该轴完全不补偿 |
| Vertical | 0–100%，1% | 100% | Pitch 补偿比例，0 表示该轴完全不补偿 |
| Start Bullet | 1–10，1 | 2 | 原版本轮射击序列的第几发开始响应；达到阈值前持续采样但不输出 |
| Smooth | 0–100 ms，1 ms | 0 ms | 时间常数；0 为即时输出，非零值平滑变化并产生响应延迟 |

初值用于第一轮功能验收，不宣称是最佳实战配置。100% 表示补偿已测得的有效角度变化，不表示全部子弹命中或零延迟预测尚未发生的后坐力。

UI 继续使用本项目字体、颜色、滑条和输入框。Horizontal、Vertical 显示为整数百分比；Start Bullet 为整数；Smooth 为整数毫秒。四个参数足够，不增加逐枪几十个页面，也不在界面暴露偏移、Hook 地址或内部状态。

补偿只针对本地玩家，没有目标选择和队友判定，因此无需 Team 开关。Hide in ArrayList 保留在模块右键菜单。模块名称、四个参数和绑定由现有配置系统管理。

## 5. 算法约定

### 5.1 输入输出

每个有效输入样本至少包含：会话代数、本地 Pawn 完整句柄、武器完整句柄、物品编号、命令序号、样本序号、预测 tick 与 fraction、原版样本视角、当前有效 AimPunch、射击序列及武器状态。

输出是该输入样本应增加的 Pitch/Yaw 角度修正。保持 Roll 为原版允许值，不把 NaN、无限值或异常跨度送入游戏。

### 5.2 补偿与平滑

在一个连续补偿区间内，用阈值前的最后一个有效样本建立后坐力基线。将 Pitch/Yaw 分别按 Vertical/Horizontal 加权，对相对基线的角度变化取反，得到累计目标修正。Yaw 差值使用最短角度差，跨越 ±180° 时不得突然整圈转动。

Smooth 为 0 时立即采用目标修正；非零时按真实样本时间间隔平滑，系数为 `1 - exp(-dt / tau)`。tau 使用秒，界面毫秒需要转换。零/负 dt 不推进滤波器，时间倒退转入重新建立基线流程。

正常前向执行时，只把“本次累计修正减去上次已应用累计修正”的增量合入原版视角。这要求输入适配器明确原版角度是否已包含上次反馈；不同来源的绝对角度和增量角度不能混用。最终的合法化/夹紧结果必须反馈到已应用量，不能把没有真正应用的修正继续累计为欠账。

原始鼠标输入只经过原版一次处理。RCS 不二次乘鼠标灵敏度，不限制用户向上/左右转动。高 DPI、开镜 FOV 和不同帧率不能改变同一角度补偿比例。

### 5.3 起始发数和射击结束

Start Bullet 依据原版射击序列与本地预测射击记录，不根据“左键按下了多久”推算。`m_iShotsFired`、武器索引及预测射击事件要交叉校验；不是任意一个整数变化都算开火。

阈值前一直更新采样基线。达到第 N 发时仅开始补偿对应的新变化，不把前 N−1 发尚未补偿的历史量一次拉回。Start Bullet = 1 的含义是第一发产生有效后坐力后的响应，不是预知第一发尚未产生的冲量。

停止射击后停止输出，不主动拉回开火前朝向，不在后台慢慢消耗剩余平滑量。下一轮建立新基线。连续点射是否属于同一轮，由原版序列状态决定，不写死一个按秒数计算的连点窗口。

原版连发已排队的剩余发数仍属于射击活动，不能仅因用户松开左键就中断。最后一发消耗完弹匣后，必须先处理本次已发生的射击，再进入空弹匣等待，避免末发被跳过。

## 6. 状态机

| 状态 | 进入条件 | 行为 / 下一步 |
| --- | --- | --- |
| Disabled | 模块关闭或宿主停止 | 不采样输出，清空会话内状态 |
| Suspended | 菜单/聊天输入、失焦、未进入对局、死亡、旁观、非枪械、数据不可用 | 不输出；恢复时重新采样，禁止补偿暂停期间积累的量 |
| Tracking | 合法本地枪械，尚未满足射击与 Start Bullet 条件 | 跟踪有效角度和原版射击序列，不修改输入 |
| Compensating | 本地预测射击活动有效且达到阈值 | 对唯一输入样本输出一次修正；停射回 Tracking，硬边界回 Suspended |

切枪、武器句柄序号变化、Pawn 更换、会话切换、数据指纹变化、预测时间不可解释地倒退，都使历史状态失效。模式切换或消音器状态变化时重新检查连续性，不把旧模式的未应用平滑量带入新模式。

重预测不是简单清空或跳过：需恢复该命令的补偿前检查点，从原始样本重算。重复回调但没有新样本时复用已有结果，不能再次扣除补偿、再次增加射击次数或再次推进平滑器。

## 7. 输入时序方案

选择原版视角采样链路中的单一接入点：原始鼠标输入已被处理、对应后坐力快照可用，但该样本尚未复制到输入历史之前。随后由原版完成当前视角、样本历史和命令构造。

`0xCB1890` 已确认处理命令历史，但不等于应直接按现有 dump 的 CreateMove 声明安装 Hook。IDA 中第三个参数被当作结构指针使用，现有外部声明却标为浮点采样时间；未经汇编和调用者验证不能采用。`0xCA8920` 已出现 Hex-Rays 局部变量分配警告，反编译签名也不可作为 ABI 证明。

实现阶段先做只观察的输入适配，确认样本形成位置、线程、参数寄存器、调用频率、命令重放及相机消费路径，再开启角度输出。若不能确认统一的上游位置，保持 RCS 不可用，不退回 Present 中直接写视角。

不得将一份“当前后坐力”填入过去所有历史条目；每个条目必须与自己的时间对应。不得改变攻击历史索引、原版开火/换弹按钮、命令节奏或网络队列。其他模块将来需要改视角时，统一走输入适配器，避免多个模块分别修改同一缓冲。

## 8. 结构与线程边界

| 拟定位置 | 职责 |
| --- | --- |
| `src/cs2/modules/combat/recoilcontrol/RecoilControl.*` | 模块生命周期、四个参数、UI 状态发布 |
| `src/cs2/modules/combat/recoilcontrol/RecoilController.*` | 补偿、平滑、状态机、命令检查点；集中在模块目录，可独立测试 |
| `src/cs2/sdk/weapons/Weapons.*` | 武器句柄、物品编号、模式、弹量、装填及射击序列快照 |
| `src/cs2/sdk/weapons/AimPunch.*` | 按目标时间取得有效后坐力，封装版本相关调用 |
| `src/cs2/sdk/weapons/Offsets.h` | 本功能的版本相关字段与入口，业务代码不散落地址常量 |
| `src/cs2/hooks/InputHook.*` | 输入样本边界、重入/重放、回调计数和卸载排空 |

UI 线程只发布一份带版本号的完整设置快照；输入线程在样本边界读取它。不能同时读取一半旧 Horizontal 和一半新 Vertical。设置热改或配置切换重新建立基线，避免百分比变化突然拉头。

预测、武器服务和后坐力求值只在已确认的游戏线程使用。渲染线程不保留 Pawn、武器或服务指针，不运行后坐力内部缓存更新。输入回调内避免磁盘 I/O、无界分配和长锁。

沿用宿主现有 MinHook 所有权；新增 Hook 只撤销自己的入口。关闭模块停止修正；熔断顺序为阻止新补偿、禁用 Hook、等待回调排空、释放检查点和状态、交还宿主清理。失败时保持 DLL 可重试清理，不在执行中的回调下释放代码。不引入静态 TLS。

版本门禁应复用现有 SDK 的 client/engine 指纹校验结果，不让 Recoil Control 依赖 2DESP 或 Radar ESP 是否启用。入口校验失败只禁用 RCS，通知一次并写明原因，不能反复弹窗或关闭全部 UI。

## 9. 枪械特殊行为

| 类型 / 状态 | 处理规则 |
| --- | --- |
| 常规自动枪 | 根据实际后坐力连续反馈，射速只参与状态校验 |
| 半自动手枪 / 狙击枪 | 仅响应有效射击序列；用户可将 Start Bullet 设为 1；不自动连点 |
| Glock / FAMAS 连发 | 识别原版剩余连发和模式状态；松键后的排队射击继续计入 |
| M4A1-S / USP-S | 以物品编号识别，结合实际消音器/模式状态；不按实体基础名称套值 |
| AUG / SG553 / 开镜枪 | 使用当前模式求值，不把视野缩放再次当成后坐力倍数 |
| R8 | 主/副射击和预备击锤阶段区分；没有实际射击就不启动补偿 |
| 霰弹枪 | 一次发射计一次射击，不按弹丸数量多次补偿 |
| Negev 与长喷 | 跟随原版当前索引和有效角度；不自造恒定轨迹 |
| 切枪 / 换弹 / 拔插消音器 | 清理不能延续的历史量，不阻止原版操作 |
| Zeus / 刀具 / 投掷物 / C4 | 不补偿 |

## 10. 验收标准

| 层级 | 场景 | 通过标准 |
| --- | --- | --- |
| 数据 | 编号、枪种、主副模式、标量展开、资源哈希 | 35 个唯一编号；980 个双模式数值可溯源，无漏项或零值误补 |
| 纯补偿逻辑 | 零变化、单轴变化、强度 0/50/100%、跨 ±180° | 输出满足定义；关闭轴为零；无反向整圈跳变 |
| 时间行为 | 同一轨迹在不同采样率、Smooth=0/非零 | 0 ms 即时；非零随时间一致，误差容限在测试中按插值步长说明 |
| 输入幂等 | 相同样本重复处理、重预测、顺序前进 | 不重复累计；从检查点重算得到相同结果 |
| 起始发数 | N=1/2/10、喷射中开启、快速启停 | 阈值前不输出，不一次补偿历史欠账 |
| 硬边界 | 切枪、死亡、旁观、断线、菜单、失焦、无效指针 | 输出立即归零且历史失效；恢复不拉头 |
| 射击边界 | 最后一发、连发余弹、R8 预备阶段、霰弹枪 | 不漏末发、不多计弹丸、不在未开火时输出 |
| 一致性 | 当前相机、命令角度、历史样本 | 同一时刻使用一致修正，不出现只动相机或只有命令变化 |
| 共存 | 2DESP、Radar ESP、Team、HUD、SMTC | 不改变模块开关和数据；渲染暂停不使压枪节奏变化 |
| 生命周期 | 关闭、DEL/自定义熔断、再次注入 | 无残留修正、Hook 排空、实例正常释放、无静态 TLS |

静态解析与导出一致性在设计阶段检查；纯逻辑和 Hook 生命周期在实施阶段用独立程序验证；游戏实射由用户完成。不得用构建通过代替实射结果。

## 11. 实施顺序与交付边界

1. 完成武器/AimPunch 只读快照与指纹适配，确认线程和求值 ABI。
2. 只观察输入样本形成链路，确定上游接入点及重放检查点；验证相机和命令使用的坐标、缩放和时间一致。
3. 实现集中于 recoilcontrol 目录的补偿控制器，通过纯逻辑测试。
4. 接入 ModuleManager、配置、绑定和现有 UI；启用单一输入输出链。
5. 验证卸载与回归，构建 DLL，由用户按枪械/场景矩阵进行实射。

设计阶段交付完整静态资源、补充逆向证据和本文档。后续实现与独立验证见 [实施记录](cs2-recoil-control-implementation.md)；尚未完成的真实游戏输入时序和实射验收保持单独标注。
