# LegitCrystalAura

持续启用的 Combat 模块，原生 C++/JNI 实现。当前适配 Lunar 1.21.11 和 Minecraft 26.3；其他版本开启时提示并关闭。不会往游戏写入 Java 类。

## 使用与设置

`Place → Auto Base → Place Delay` 独立控制连续提交黑曜石底座的最小间隔，默认 0 ms，范围 0–1000 ms，步长 5 ms。首次底座可立即放置；底座冷却不阻止后续水晶，水晶仍使用 `Place → Delay`。等待时继续预瞄合法候选，预测耗时计入剩余底座冷却。新参数通过现有配置系统保存，旧配置缺少该参数时使用默认值。

与 KillAura 协作时，有效放置计划在放置 Delay 内继续预瞄；底座/水晶确认的有限等待窗口保持已提交的转头，避免每个等待 tick 让 KillAura 把朝向拉回玩家。Delay 只限制实际使用物品，未缩短发包间隔。无水晶、失去目标、当前安全检查失败或自救模块接管时让位；搜索尚未找到合法计划时也不占用 KillAura。回归模拟中优先级 Aura 在等待确认和 Delay 时不能抢转头，缺物品和自救时可正常恢复。

`Only Above Crystal` 仅限制实际放水晶和引爆，不提前阻止 Auto Base 施工。普通近战击退的腾空可能不足一格，邻近黑曜石底座仍可合法放置；施工仍满足伤害、安全、距离、支撑面及当前占位条件。底座建成不表示水晶立即可放，后续仍检查高度与水晶空间。搜索列表不再按生成时的目标脚部高度永久删掉候选。回归包含平地击起不足一格、默认转头速度以及穿墙开关两种状态。

快捷栏准备末地水晶，模块在 Range/FOV 内选择玩家，复用 Teams 和 AntiBot，自动放置并等待实际水晶实体出现，再瞄准引爆，不预测实体 ID。默认使用已有黑曜石或基岩；开启 Auto Base 并准备快捷栏黑曜石后，可以先自动放置底座。

| 设置 | 默认 | 含义 |
|---|---|---|
| Target → Range / FOV | 4.5 / 180° | 目标选择范围；放置和攻击还受原版交互距离限制 |
| Target → Through Walls | 关 | 放置和引爆忽略方块遮挡，仍要求当前转头射线命中对应底座/水晶且在交互距离内 |
| Place → Delay / Auto Switch | 0 ms / 开 | 自动放置、切到快捷栏水晶，连续工作期间保持使用槽位，停止后恢复原槽 |
| Place → Silent | 关 | 使用现有 slot spoof：只改变实际交互槽位，快捷栏选择及手持显示保持玩家原物品 |
| Place → Auto Base | 关 | 将可新建底座的位置加入同一选位计划，自动切黑曜石放底座再衔接水晶；需要 Auto Switch 开启且快捷栏同时有黑曜石和水晶 |
| Break → Delay | 0 ms | 自动引爆的最小间隔 |
| Swing | 开 | 控制放底座、放水晶和引爆时的本地挥手；关闭后仍发送必要的挥手包 |
| Place ESP | 开 | ImGui 绘制当前放置底座方块，轮廓和半透明填充随客户端主题色 |
| Rotation → Speed | 45°/tick | 静默平滑转头，复用 RotationManager 的移动修复 |
| Safety → Only Above Crystal | 开 | 目标脚底 Y 低于水晶底部 Y 时，既不放置也不引爆 |
| Safety → Ignore Self Damage | 关 | 跳过自身伤害读取、伤害上限和剩余血量限制；目标伤害和队友保护仍生效 |
| Safety → Min Target Damage | 4 | 最小估算目标伤害 |
| Safety → Max Self Damage | 6 | 最大估算自身/队友伤害 |
| Safety → Min Remaining Health | 4 | 自身/队友预计剩余生命加吸收值下限 |

伤害与生命参数使用生命点：2 点为 1 颗心。Only Above Crystal 比较的是**目标**，同高度允许；放置前采用底座 Y+1，引爆前读取实体当前 Y。两个动作提交前都会重新检查高度和伤害，所以转头途中目标掉下去会停止操作。关闭该开关仍保留其余伤害检查。

## 交互和恢复

- Auto Base 仅在空气格放黑曜石。参考 Mio，施工前同时检查底座一格占位和上方两格水晶生成空间，要求上方一格空气、存在可点击的邻接方块。空中玩家身体占据水晶空间时，不再先建一个暂时无法使用的脚下底座，而是寻找可用的相邻位置；完全高于生成空间时仍允许脚下施工。新底座 Y 不高于目标当前脚部 Y+1.5。不会往玩家身体内部放方块，也不会凭空放置无支撑方块、挖掘原方块或连续搭支撑链，避免点击会打开菜单的方块。优先使用下方支撑，其次侧面/上方支撑。瞄准实际邻接面后才切槽，原生提交入口再次检查底座和水晶空间。确认窗口内不重复放底座，读到黑曜石/基岩后才放水晶，超时重新检查并允许重试。
- Only Above Crystal 约束实际放水晶和引爆，不提前阻止底座施工。放成后会基于新世界遮挡再次检查。
- 使用原版控制器。默认使用世界射线命中结果；Through Walls 开启时计算当前射线与底座/水晶包围盒的交点，并给放置提供相应方块面。不会跳过转头、距离或可放置性检查；服务器仍可能拒绝穿墙交互。底座为黑曜石/基岩，上方一格空气，原版 1×2×1 生成区域没有实体（包括自己）。
- 持续循环放置/引爆，每 tick 最多一次交互。放置后等待实体出现；引爆后等待实体消失。收到确认即可进入下一动作，无额外固定停顿；确认最多等待 200 ms，超时后重新检查并允许重试，不使用旧目标 ID 直接攻击。用户设置的 Delay 仍是最小动作间隔。
- Auto Base 开关两侧使用同一选位流程，优先级为无遮挡水晶位置、需要 Through Walls 的水晶位置、新建黑曜石。同阶段比较预测目标伤害，不再扣除等待时间、施工成本或自身伤害作为排序项；自身/队友安全仍为硬性限制。地面施工完成分批搜索后执行，空中允许三批后选用已评估的最佳位置。已施工底座优先衔接水晶；若施工后生成空间被占用，先等待 6 tick，期间允许使用其他已有底座。持续阻塞后重新搜索，并允许建造合法替代底座。没有合法替代位置仍保留原底座等待，不重复向占位格施工。底座确认超时后，对该位置暂停重试 500 ms。
- ESP 在选位、瞄准和等待确认期间显示；失去目标、无可用物品、危险/遮挡、模块让位、禁用或换世界后清除。渲染线程读取带世界标识的快照，使用当前帧投影，250 ms 未更新的快照不绘制。
- 放置事务拒绝同 tick 已发生的攻击，并阻止后续原生攻击；其他现有物品使用调用保持原有行为。
- 切槽只发生在准备提交放置时。连续工作期间保持水晶槽位；Auto Base 只在确实需要时切黑曜石，随后直接切水晶，不经过原槽。失去目标、无法继续工作、关闭模块或进入其他界面时恢复；恢复同步失败重试。玩家手动换槽或原槽物品变更时不覆盖玩家新选择，换世界丢弃旧任务。Silent 开关在工作中改变时先结束旧切槽会话，再以新模式开始。
- 连续持槽在 tick 开始时允许其他模块接管，但不恢复实际槽位/清空 spoof，因此不会每 tick 来回同步。接管者持有槽位期间不会被本模块恢复动作覆盖，结束后才处理原槽恢复。其他模块默认保持原有独占规则。
- AutoMace、AutoMLG、AutoCharge、Scaffold、Refill、正在使用物品的 AutoBlock/AutoRod，以及正在延迟发包的相关模块优先。上一 tick 的转头所有权释放，槽位可由这些模块接管。
- 水晶模块在 KillAura 之前规划可执行动作并申请独占转头，实际交互仍在 PrePlayerInteract 阶段复检、提交。水晶转头/放置/引爆时，KillAura 暂停转头、普通攻击、AutoBlock 攻击投递及暴击疾跑干预；水晶缺物品、没有安全可用位置、等待确认或禁用时让位。每 tick 只进行一次平滑转头步进。
- 无可用水晶不会执行自动放置，但 Break 可以引爆已有且满足条件的水晶。找底座按 tick 分批扫描，避免每帧完整扫描周围方块。

## 伤害模型与验证边界

### 移动预判与统一选位

每游戏 tick 读取自己和目标的位置差、包围盒与着地状态。急停、反向移动立即使用新方向；单 tick 位移大于 1.5 格按传送/异常移动处理，不继续沿旧速度外推。切目标、换世界或让位给其他模块后重新采样。

短期预判最多 8 tick：地面采用观测水平速度，空中额外使用普通重力/垂直阻力近似；每次位移按不大于 0.25 格分段，调用原版碰撞查询阻止预测位置穿进障碍，允许未受阻轴继续移动。它不是完整游戏物理模拟，未精确模拟走出悬崖、特殊药效、液体、攀爬或目标未来输入。

已有底座和新底座共同参与选位。无论 Auto Base 是否开启，都使用跨 tick 搜索：每 tick 最多访问 128 个网格、详细评估 2 个新候选，并在候选之间检查 2 ms 软预算（单次 JNI 调用无法中途打断；旧计划复检另计）。准备/交互回调共用预算；先排除无支撑格再进行实体和伤害查询。地面施工等待搜索完成；自己或目标在空中时，搜索满三批后可采用已评估候选中伤害最高的合法底座。已找到合法水晶位置则允许本批结束后执行，但不丢弃剩余扫描进度，后续继续寻找更优位置。已有最佳候选和最终提交位置仍会复检。同阶段保留有效旧位置，只有新伤害超过旧伤害及其四舍五入值时才换位；相同伤害不随遍历顺序抖动。已施工底座优先完成水晶衔接。未施工底座计划最多复用 6 tick，目标移动超过 0.75 格则重新规划。大幅位移会丢弃旧搜索；未找到候选时目标急停/变向也重启搜索，避免沿用已跳过的位置。

预判时长由实际半距离平滑转头步数、动作间隔与近期世界状态确认耗时估算，Auto Base 额外计算放底座及切向水晶步骤。确认耗时平滑限制在 1–4 tick，来自客户端观测，并非真实服务器 RTT；放置/引爆的确认等待窗口据此在 200–300 ms 间变化。已有底座的水晶生成空间检查当前与按转头/确认耗时估计的 1–3 tick 路径。施工时先检查真实水晶空间，再按 Mio 的方式检查目标水平预测包围盒，保持当前垂直边界，避免下落预测把整段竖直空间提前封死。伤害预判将待放底座同时纳入运动碰撞和爆炸遮挡。只对路径经过底座的实体额外预测，并缓存同 tick 同候选结果；服务器未接受底座时不视为真实落地。已有底座按当前眼睛位置检查距离，新底座额外检查 1 tick 后的距离。

预测伤害对移动后的包围盒重新做暴露采样，计划中的黑曜石作为虚拟实心方块参与射线遮挡，不修改游戏世界；实际底座出现后再次读取真实世界。未来伤害处于 2 点以上但低于最低伤害时，参考 OpenMio 用当前包围盒伤害回退校验。当前自身/队友安全条件始终检查，因此虚拟保护墙不会取消实时安全限制。

同阶段只按预计目标伤害排序，自身和队友安全仍是硬性限制。搜索分批进行，水晶可提前执行，因此不能保证瞬时或服务器实际伤害的绝对最大值。预判超过 8 tick 的部分不继续外推。底座只要求原版方块放置距离，水晶攻击距离在实际水晶阶段检查。实际提交仍要求当前转头命中、真实可放置性和原有安全条件通过。

水晶爆炸强度 6、伤害半径 12。当前伤害使用原版 `ServerExplosion.getSeenPercent`；预测伤害沿用原版/OpenMio 包围盒采样间距，通过原版 COLLIDER 射线查询世界遮挡，另外处理虚拟底座。标准站立玩家每次约 45 个样本，JNI 复用同一局部帧、世界和爆炸终点，及时释放逐射线对象；同 tick 同实体/位置/包围盒/施工阶段的预测暴露结果复用。之后计算距离、难度、护甲/韧性、抗性效果、保护/爆炸保护附魔。Y 不是唯一伤害条件。任何必要数据读取失败都会拒绝操作。

为避免链式爆炸突破伤害上限，候选位置/被引爆水晶 12 格内有其他水晶时跳过。服务器插件、自定义附魔/数据包、延迟期间移动、同 tick 的其他伤害仍可能改变实际结果；估算并非绝对防死亡保证。

### OpenMio 对照与适配范围

参考 `skid/OpenMio-main/src/main/java/me/mioclient/module/combat/AutoCrystal.java` 的 `getAutoCrystalData1131`（选位）、`do1132`（提交前伤害复检）、`do1134`（底座衔接）、`is1151`（底座复用）；`AutoCrystalSearchHelper4.is2070`（预测占位）；`ArmorSearchHelper4.get1900/get1902`（预测包围盒伤害、虚拟实心底座）；`PlayerEntitySearchHelper4`（分轴碰撞预测）。预测碰撞按 Y、较大水平轴、另一个水平轴处理，撞墙时有界二分保留可移动距离。

不是逐字复制：对齐 OpenMio 的施工前水晶空间检查、阶段优先级、同阶段目标伤害排序、旧位置伤害门槛和新底座高度上限。Mio 的 NONE/RAYTRACE 在本项目映射为无遮挡/需要 Through Walls，沿用本项目交互距离与穿墙开关，不新增 Mio 的 wallRange/smartTrace。仍按本项目粘性目标选择评估一个目标，不改成 Mio 的每位置遍历所有敌人；施工水平预测目前检查当前目标，所有实体的实时占位仍由原版查询确认。不移植异步读取游戏世界、空气放置、预测实体 ID、低爆炸抗性方块忽略及 20 tick 全量预测。保留现有 8 tick 预测、原版伤害与安全限制、分批预算、实际实体确认、Silent/Swing、共享转头/移动修复和高于 KillAura 的优先级。

连续循环回归覆盖 20 轮确认后立即再放、缓存底座的伤害/遮挡复检以及 ESP 快照清理。旧配置中已保存的 Delay 不会被覆盖；需要最快循环时将 Place / Break 的 Delay 都设为 0。实际速度仍受服务器确认和转头速度影响。

开关回归覆盖穿墙放置/引爆、六个命中面与距离边界、慢速转头未到位时不交互、忽略自身伤害与队友/目标保护的独立性，以及关闭开关后缓存底座重新检查。Ignore Self Damage 不取消其他水晶引起的链式爆炸限制。

Auto Base 回归覆盖完整底座/水晶/引爆循环、无水晶/黑曜石、无空间/支撑、穿墙开关、关闭切槽、伤害拦截、等待确认、禁用恢复和手动换槽。移动回归覆盖左右对称候选随移动方向改变、新建底座与水晶使用同一位置、目标进入施工区域时停放、急停、反向、传送、障碍截断、落地及底座确认超时暂停重试。

## 转头与连续交互

Grim `DuplicateRotPlace` 比较放置对应的 yaw 变化：变化大于 2° 且与上次放置的变化差小于 0.0001 时记录违规。旧版固定底座中心与水晶近侧角之间的往返转头会重复相同变化。现在放置和引爆优先沿用已命中的现有射线；转头接近目标时减小步长。放置以实际射线命中为准，不再要求 yaw 步长小于 1.5° 或完全对齐方块面中心，因此横移、绕行时仍能放置。

模块记录 Post Motion 的真实转头变化与自身放置历史，只拦截重复的大幅 yaw 步长；没有实际转头的 tick 不会清除保留的变化。底座/支撑面同时提供多个有效面内瞄准点，避免一直等待已经失效的中心角度。保留灵敏度量化、移动修复和共享事务，不改全局转头管理，也不追加随机角度包。历史仅覆盖本模块交互，其他模块或手动放置不属于此记录。

回归覆盖 20 轮连续放置仅首次切槽、Silent 显示槽位不变、Auto Base → 水晶静默切换、Swing 关闭时无本地挥手、手动滚轮、切换 Silent、抢占与恢复。移动测试以约 0.27 格/tick 持续绕行 100 tick，交叉覆盖普通/Silent、已有底座/自动底座、灵敏度量化开启/关闭，并检查实际射线与重复大幅转头。还按 Grim 保留最后一次实际转头 delta 的方式检查大幅转向后连续放置。静态和模拟通过不等于服务器实测通过。
