# AutoReplenish

Player 分类的独立快捷栏补给模块，默认关闭。启用后记住快捷栏 0–8 各槽的物品；物品耗尽变空后，从主背包 9–35 查找相同物品并补回原槽。不会填充启用时就为空的槽位，也不把其他快捷栏的物品搬过来。

匹配使用原版深拷贝与 ItemStack.matches，仅将副本的数量归一为 1；保留组件/NBT、附魔、药水类型、自定义名称等，数量不同也能匹配。不修改真实堆叠。一个 tick 最多一次 SWAP，目标槽在提交前必须仍为空，选中槽位和鼠标上的物品不变。没有储备时继续等待，不丢弃或替换其他物品。使用后变成空桶/玻璃瓶等非空物品不触发补给。

设置只有 Delay（默认 0 ms，0–1000，步长 5）和 Grim（默认关闭）。Delay 从观察到空槽开始计时；未确认的交换至少间隔 250 ms 重试。

Grim 与 AutoTotem 一样：申请共享攻击/使用事务，暂停移动、跳跃、蹲下和疾跑，等待 MoveInput 与 Post Motion 完成，下一 tick 再交换，随后释放暂停；满足原先疾跑且仍按前进的条件才请求恢复疾跑。等待超时、禁用、换世界、切换界面或被其他事务占用会退出。它不是服务器兼容性的保证。

AutoTotem、Refill、ChestStealer 优先；补给工作时 InvManager 让位，Sprint 尊重其移动暂停。打开游戏界面、鼠标携带物品或其他背包模块工作时清除槽位记忆，关闭后重新建立，避免把手动整理当成耗尽。仅凭空槽不能区分丢出最后一个物品和消耗，因此游戏内直接丢空已记忆槽位也会触发。

与现有深拷贝适配一致，支持 1.9+ 配置的库存接口；旧 Lunar 1.7/1.8 不执行。Grim 与 AutoTotem 同样只在 UsesModernRuntime 配置执行。Lunar 1.21.11 与 26.3 的新增/复用堆叠绑定通过真实 jar 检查；Forge 普通模式使用现有 SRG 库存适配，尚未实机验证。

验证：`Client/test/player/autoreplenish/run.ps1` 直接编译生产模块，覆盖耗尽、原槽补给、不同身份、延迟与重试、GUI/游标重置、Grim 输入等待、事务冲突、禁用和换世界。`Client/test/combat/autototem/run.ps1` 验证原模块回归。构建与模拟不等于实机验证。
