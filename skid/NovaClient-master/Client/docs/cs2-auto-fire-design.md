# CS2 Auto Fire 设计

状态：已实现原生 C++ 模块并接入共享输入链路。基线：2026-09-25 / CS2 Build 14184。游戏内注入、实射验收由用户完成。

## 用户行为

在 Combat 中增加独立模块 `Auto Fire`。开启后，当前射击方向的射线首先命中有效玩家、武器能够射击时，自动触发主攻击。瞄向空气、被方块/墙体挡住、目标死亡或离开射线时，撤销模块的开火请求。

模块不修改角度，不依赖 Aimbot 开启，不使用 Aimbot 的 FOV 范围或候选目标代替实际命中。是否忽略队友由现有 `Team` 模块统一决定。

## 设置

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| Delay | 0 ms | 同一个有效目标连续处于射线中多久后开始开火；范围 0–500 ms，步长 1 ms |
| Scoped Only | 关闭 | 开启后，狙击枪必须处于开镜状态才自动开火；普通枪械照常 |

复用现有模块开关、配置、ArrayList 和 Toggle/Hold 按键体系，默认 Toggle。其余参数不添加独立开关：武器冷却、弹药、换弹、切枪、玩家状态始终检查。不开设 CPS、Aim FOV 或第二份 Team 设置。

`Delay = 0` 表示不额外等待；检查和触发仍随游戏输入更新执行。延迟只作用于首次连续锁定，同一目标上的持续射击遵循枪械冷却。目标改变或失效立即重置延迟。

## 输入与射线

1. 仅在游戏原生输入线程读取本地玩家、当前武器和当前输入样本。菜单、聊天、控制台、失焦、死亡、观战、断线、输入被游戏抑制时不生成自动攻击。
2. 按现有顺序处理 Recoil Control 和 Aimbot，得到本次最终输入角度。结合与原生射击一致的 AimPunch 计算实际射线方向；不能遗漏后坐力或重复叠加补偿。
3. 从武器服务提供的射击起点调用原生射线，读取首先命中的实体。检查实体完整句柄、所属 controller、存活、免疫和 Team 状态；射线异常或实体身份变化时不射击。
4. 校验弹药、换弹、消音器切换及 `nextAttack`，执行目标延迟状态机。
5. 在原生攻击输入被消费之前提交自动攻击。手动攻击与自动攻击按 OR 合并，只释放本模块拥有的请求，不撤销用户物理左键。

`AimSnapshot.cpp` 共用射击起点和底层 TraceLine 结果。Auto Fire 每个样本只检测当前射线，并要求命中实体的 controller 完整句柄与 controller 指向的 Pawn 一致，不扫描整个 Aimbot FOV。

2026-09-25 实机诊断发现两处射线适配错误：

- 输入和武器采集成功时，旧实现持续停在 `ray=solid flags`。Build 14184 的 `0x1773970` 会在普通点射线（shape +0x28 为 0）命中时设置结果 `+0xBC=1`，它不是 `allSolid`。现统一解析命中实体 `+0x8`、fraction `+0xAC`、startSolid `+0xBB`，删除对 `+0xBC` 的错误拒绝。修正同时用于 Aimbot 可见性，测试覆盖原始 192 字节射线结果。
- 仅修正标志后，实机仍没有玩家目标。原通用 `0x827320 → 0xA1A260` 链路会移除 contents bit 2，再检测通用物理碰撞，不能代替 gameplay 玩家命中框检测。改为原生准星函数 `0xC9AB10` 使用的两阶段调用：`0x3520D0` 构造 layer 3 过滤器，`0x2006D0` 检测世界；随后构造 layer 4 过滤器，`0xAC9CA0` 补做玩家检测。两阶段使用完全相同的射线起终点，玩家检测 fraction 参数传 -1，沿用世界碰撞距离，只允许更近的玩家命中替换世界结果。没有墙穿或用 HUD 缓存索引直接开枪的回退。

Schema 中 `C_CSPlayerPawn::m_iIDEntIndex` 可作为分析参考，不作为唯一触发依据，避免依赖 HUD 更新时机或未经身份验证的实体索引。

## 已接入的原生开火适配

`Sample.attack` 仅供 RCS 读取，实际开火由 `Weapons.cpp` 合并当次原生输入样本。通过 Build 14184 IDA 和 PE 字节核对的关键入口如下：

| 入口 / 布局 | 实现契约 |
| --- | --- |
| `0xB7C070` | ProcessInput 外层 Hook，ABI `void(input, int slot, float dt)`；只处理 slot 0 |
| `0xBEFF40` / 返回 `0xB7C518` | 最终角度提交，先完成 RCS/Aim，再用最终角度 + 有效 AimPunch 做射线 |
| `0xB63F80` | 原生采样验证：sample +0/+8/+16 分别是 held/pressed/released |
| `0xB5F6C0` | 每次分配 0x440 字节样本并清零按钮；自动请求不写全局 kbutton |
| `0xB78AE0` | 两个输入虚表的最终回调均为空函数；运行时再次核对，外层返回后才合并攻击 |
| `0xB603C0` | 后续消费样本到 UserCmd，合并 held/pressed/released 和 subtick moves |
| `0xCFC150` | 原生鼠标输入 gate，检查输入界面占用；采集及提交时再次检查 |
| `0x3520D0 / 0x2006D0 / 0xAC9CA0` | 原生过滤器构造 / 世界射线 / 玩家命中框检测；三个入口独立字节验证 |
| sample +44/+48 | subtick 数量/32 字节记录，上限 32；只处理主攻击，保留移动及手动输入 |
| weapon +0x388 | 本版本原生 VData 指针；读取 fullAuto +0x72D、revolver +0x71E、range +0x830 |

最后的原生 held 写入在角度回调之后，因此不能在角度回调内提前改掩码。外层 Hook 将本样本的决定写入同一样本，原生后续消费时同时收到按键和 subtick 边沿。半自动/R8 发射确认后至少释放一个网络 tick，避免高 FPS 把按下/松开压进同一输入时刻。

不通过操作系统模拟左键，也不采用渲染线程定时写一个 attack 数值的方式。新入口保持项目现有构建号、模块指纹、入口字节校验；校验失败时仅停用 Auto Fire 的适配。

## 临时输入失败与适配故障

2026-09-25 补充：旧版把提交时取不到样本、最终样本已变化、subtick 记录满 32 条等返回 `false` 的情况一律锁定为永久故障；再次开启时又统一提示 `for this game version`，无法据此判断版本是否变化。

现在提交返回明确结果：成功按下、成功释放、样本暂缺、样本已变化、记录拒绝、实际写入异常。前三种样本问题只跳过本次提交并重置目标延迟，保留模块开关，下一次有效输入重新判定。没有成功写入的请求不会作为已经开火传给 RCS。如果上一次成功提交仍是按下状态，先在有效新样本完成自动释放，再允许重新按下；禁用期间也处理待释放请求，同时保留手动左键。

原生读写调用抛出异常时仍停用对应适配，不逐帧重新尝试异常调用。日志保留阶段、异常码、地址、累计跳过次数和最后一次跳过原因。安装缺少绑定、Hook 创建失败、Hook 启用失败、运行时异常分别记录；同一次不可用状态只通知一次，避免按住快捷键或反复开启刷屏。

用户报告此次提示偶发后又恢复，但本机可用日志停在截图之前；此次修改修复了可由代码和离线测试确认的错误分类，不能据旧日志断言截图对应的具体失败分支。实机复现时可从新增日志区分。

## 枪械与模块协作

- 全自动枪：目标有效期间保持自动攻击请求；脱离射线即撤销。
- 半自动枪：根据实际冷却及开火确认生成按下/释放，不按渲染 FPS 连点。
- 原生连发：已由游戏启动的后续连发由原生逻辑完成，不能承诺撤销已经启动的连发。
- R8：按原生蓄力、释放和再触发流程单独处理，不套用普通手枪时序。
- 刀、投掷物、C4 不自动使用；不开启自动换枪、装弹或开镜。
- Recoil Control 使用本次实际合成攻击状态以及游戏反馈的开火记录，保持连续补偿。不能只修改 `Sample.attack` 来假装枪已发射。
- Aimbot 的 `Only While Clicking` 仍按照用户物理按键判断，Auto Fire 不伪装成物理点击改变该选项的语义。

## 结构与状态

- `modules/combat/autofire/AutoFire.h/.cpp`：设置、模块生命周期与通知。
- `modules/combat/autofire/AutoFireController.h/.cpp`：无游戏内存依赖的目标延迟、枪械触发和释放状态机。
- `sdk/weapons`：扩充射击准备状态和原生攻击输入适配，沿用集中 mapping。
- `sdk/aim`：抽取原生射线结果，复用身份校验。
- `hooks/InputHook`：在正确输入阶段协调角度与攻击，UI 线程只发布设置快照。

状态机为 `空闲 → 等待 Delay → 自动射击 → 释放/重置`。半自动另有等待冷却和释放沿状态。状态绑定本地 Pawn、武器完整句柄和目标完整句柄；换人、换枪、断线、禁用或熔断均清理。

沿用 frame、ordinal、time 与实体身份区分输入样本；同一输入样本重放时重用决策，不重复累计 Delay 或生成新的攻击沿。不能按 FPS、Present 次数或同一帧 Hook 调用次数计时。
