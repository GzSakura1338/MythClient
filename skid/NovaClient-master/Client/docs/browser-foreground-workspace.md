# Chrome / ClickGUI 前台调度

日期：2026-09-27。状态：Chrome 与 Panel ClickGUI 已接入，游戏内验证由用户自行注入。

## 首版实现说明

- Settings 中新增 `Stage Manager`，默认开启并随配置保存。开启时 Panel ClickGUI 通过 ESC 或快捷键关闭会自动收回左侧；关闭设置会清除调度缩略图并恢复直接关闭行为，Chrome 浮窗回归内嵌，保留浏览器会话。Classic 保持原行为。
- 左侧卡片布局按帧平滑插值，窗口加入、恢复和显示尺寸变化时上下移动，不再直接跳到新的居中位置；命中区域与卡片同步移动。

- 浏览器标签栏右上角的重叠窗口按钮进入前台调度，关闭 Panel 后独立窗口继续显示。标题栏提供停靠、收纳、最大化/还原和关闭；支持拖动标题栏、双击最大化、四边/角缩放。
- 点击减号或在没有编辑/弹窗时按 ESC，窗口缩到左侧预览；打开 ClickGUI 解锁鼠标后点击预览恢复。点击窗口外部也收纳；后台预览不向网页发送鼠标事件。
- Panel 左上角 Logo 旁新增收纳按钮。ClickGUI 收纳后生成独立缩略图，保留当前页面、搜索和设置；使用原 ClickGUI 快捷键或鼠标已解锁时点击缩略图恢复。Chrome 与 ClickGUI 切换时，原前台窗口收到左侧，两者同时收纳时纵向排列。Classic 暂不提供收纳入口。
- 调度逻辑集中在 `src/ui/workspace/ForegroundWorkspace.cpp`；暂不建立通用多应用注册系统。`BrowserPage::DrawView` 是内嵌/浮窗共用视图，没有复制一套浏览器控件。Panel 预览由 `PanelSnapshot.h` 保存 CPU 绘制数据，仅重放当前字体图集对应的文字和几何，不缓存模糊、网页纹理或逐帧回调；资源重建/卸载时清理快照。
- 修复最大化后的子窗口遮挡：Chrome 仅在进入前台时获取一次焦点，移除每帧将父窗口强行置顶的逻辑，让 ImGui 正常维护弹窗层级。
- 左侧视觉按 macOS 参考调整：卡片宽度最高 190px，高度根据窗口比例计算，并在小屏幕压缩整组；卡片按屏幕纵向位置向中心倾斜，右侧透视收窄，悬停展平。左下角使用最高 42px 的圆角应用图标，Chrome 使用彩色标志，ClickGUI 使用 N 字标。透视同步调整裁切矩形，图标不跟随窗口倾斜。
- 位置尺寸写入浏览器独立 `settings.ini` 的 Window 段，启动仍以内嵌模式为默认。最大化状态不持久化，保存的是可还原矩形。
- 预览复用网页纹理与精简框架；当前会话、标签、登录态在分离/停靠中保留。新增独立输入捕获查询和两端宿主接入。
- 后续扩展：多应用分组、侧栏边缘唤出、网页全屏优先处理 ESC。当前 ESC 优先关闭 Nova 弹窗/输入框，其次收纳浮窗；不承诺完整复刻 macOS 的全套行为。

以下保留最初的目标设计，其中“首版”描述的是最初仅 Chrome 的阶段；当前实施范围以上方说明为准。

验证记录：Release DLL 构建和静态 TLS 检查通过；OpenGL 预览验证分离、拖动、缩放、最大化/还原、设置弹窗在父窗口之后绘制、Panel 收纳按钮/快捷键/缩略图恢复、双卡片边界与输入释放、ESC 与停靠会话连续性；DX11 原生集成验证 Panel 关闭后的浮窗、输入捕获释放、交换链重建、浮窗状态下卸载与同进程重新挂接。未向用户游戏注入；Vulkan 实机表现仍待测试。

## 目标与范围

在浏览器标签栏右上角增加「前台调度」图标（左侧小卡片与右侧主窗口，约 28×28 逻辑像素），占用固定区域；标签数量再多也不能挤占。点击后，把现有 Chrome 页面从 Panel 中分离成游戏内独立 ImGui 窗口，可以像桌面窗口一样拖动、缩放、最大化、恢复和置前。后台窗口参考用户提供的 macOS 前台调度截图，收纳为屏幕左侧纵向排列的窗口缩略图。

首版是游戏画面内的桌面式窗口，不创建 Windows 原生浏览器窗口、不跨显示器拖出游戏。浏览器继续复用现有 CEF 进程、标签、登录态、地址栏、网页纹理和输入桥。切换展示方式不得重新导航或重启浏览器。

## 用户交互

- 内嵌时：红框位置显示「前台调度」图标，悬停提示“移至前台调度”。
- 分离时：默认关闭 ClickGUI，Chrome 独立居中并获得焦点。首次大小使用约游戏视口 75%×75%，以后恢复上次矩形。左侧分类和客户端 Logo 不出现在浮窗内。
- 浮窗标题栏：左侧为 Chrome 名称和拖拽空白区，右侧为「回到 ClickGUI」「最小化」「最大化/还原」「关闭」。下方保留网页标签与地址工具栏。浏览器标题栏没有空置的大高度。
- 拖动：只由标题栏空白区发起，不允许从网页内容、标签关闭按钮、地址栏发起拖动。双击标题栏最大化/还原。
- 缩放：四边和四角可拖动，正确显示鼠标缩放光标，立即更新边框和输入坐标。最小尺寸建议 480×320 逻辑像素；小视口优先保证可见，不强制超出屏幕的最小值。
- 最大化：填满游戏可用视口，保留小边距；还原回最大化前的位置尺寸。最大化后拖动标题栏可还原，并保持抓取点比例。
- 收到侧栏：原最小化按钮执行“收至左侧”，保留 CEF 和标签，主窗口缩入左侧 Chrome 缩略图，释放焦点。点击缩略图恢复上次窗口矩形并激活，不重新加载页面。
- 关闭浮窗：关闭展示并回到默认内嵌状态，不清除标签；下次点击 Chrome 导航显示同一会话。真正停止浏览器仍由已有电源按钮负责。
- 回到 ClickGUI：恢复 Panel 的 BROWSER → Chrome，原会话重新挂载在内嵌区域；保存浮窗矩形，便于再次分离。
- 在 ClickGUI 内再次点击 Chrome，如果浏览器已分离，则恢复并置前已有浮窗，不再创建第二份浏览器视图。

## 焦点与键鼠规则

窗口可见不等于正在操作。独立记录展示状态和焦点，避免游戏旋转镜头时无意点击浮窗。

| 状态 | 显示 | 输入与光标 |
|---|---|---|
| 内嵌 | 由 Chrome 页面显示 | 复用 ClickGUI 的交互会话 |
| 浮窗获得焦点 | Chrome 显示在 ClickGUI/HUD 之上 | 解锁光标，阻止键鼠向游戏和模块按键穿透 |
| 浮窗失焦 | Chrome 保持可见 | 浏览器停止接收输入；ClickGUI 若打开则归它，否则回到游戏 |
| 收到侧栏 | 左侧窗口缩略图 | 游戏保持正常输入，浏览器执行已有后台音频策略 |

ESC 按优先级逐层退出：IME/地址编辑或子菜单 → 网页全屏 → 将前台窗口收到左侧并释放焦点 → ClickGUI。一次按键只处理一层。重新打开 ClickGUI 即获得可操作鼠标，可点击左侧缩略图恢复 Chrome；游戏捕获鼠标时不响应侧栏悬停或点击。后续可以配置独立的“前台调度”快捷键，首版不占用新的默认游戏按键。

点击空白区域结束浮窗交互时，消耗该次按下及配对释放，不把它变成游戏攻击。焦点转移需通过现有宿主接口释放鼠标锁定、同步按键状态；之前按下的键必须完成释放，不能通过简单丢弃所有 KeyUp 留下卡键。拖动和缩放期间保持输入归属，鼠标超出窗口仍可完成操作。

熔断键优先级始终最高，网页输入不能屏蔽；Alt+Tab、失去游戏焦点、窗口重建时终止拖动/缩放并清理网页按键。恢复到游戏后按照 Minecraft/CS2 各自现有规则恢复鼠标捕获。

## 左侧缩略图调度栏

参考截图左侧的窗口预览排列，不复制 macOS 底部 Dock、菜单栏或整套桌面。颜色、字体、圆角、模糊继续使用 Nova 主题。

- 左侧预留约 144 逻辑像素，卡片宽约 120，高度按窗口宽高比自适应，最大约 92；图标叠在预览左下角，悬停显示窗口名和当前标签标题。卡片垂直居中，间距约 18。
- 首版只有一个 Chrome 独立窗口，因此收纳后只有一张 Chrome 卡片；浏览器标签仍留在同一个窗口内，不把每个标签伪装成独立应用。以后注册其他独立 UI 时再按最近激活顺序纵向排列。
- 当前前台窗口不重复显示在左侧；切换到另一独立 UI 时，原前台窗口收进侧栏，新窗口恢复。ClickGUI 是进入调度的控制界面，首版不为其生成缩略图。
- 悬停卡片轻微放大、向右移出约 6 像素，边框柔和提亮；保留截图中轻微倾斜的层次感，以二维梯形顶点模拟，不增加三维渲染依赖。实际命中区使用稳定矩形，不随装饰倾斜变化。
- 收纳动画约 220 ms，窗口位置、大小、圆角连续过渡到卡片；恢复约 260 ms，反向展开。主要使用位移与缩放，避免靠渐隐掩盖跳变。连续快速切换从当前动画状态转向，不跳回起点。
- 收纳和恢复动画期间关闭菜单并暂时禁止网页点击，避免输入坐标与动画画面不匹配；动画结束恢复焦点。窗口动画不不断改变网页 viewport，只在最终尺寸确定后更新，避免视频或页面反复重排。
- 自由拖动时不强制吸附；首次位置和最大化矩形预留侧栏空间。若窗口覆盖侧栏，鼠标已解锁时靠近屏幕左缘可临时展开侧栏并置顶；游戏操作期间侧栏不因准星或锁定光标而抢焦点。
- 缩略图默认使用收纳时缓存的最后画面，保持页面辨识度，不为每张卡片持续运行额外 CEF 渲染。后台音频仍由已有设置决定。恢复时保留预览直到首张新帧到达，避免黑屏闪烁。
- 缩略图是完整 UI 的合成预览：保留网页纹理引用，按比例绘制精简标签/工具栏轮廓，不截取整个游戏画面。资源需持有到退场动画结束；设备重建时从缓存 CPU 帧重建。
- 没有后台窗口时收起侧栏，不留下大块空面板。条目超出高度时仅侧栏滚动，不影响网页滚动或游戏输入。

## 架构拆分

建议新增 `src/ui/workspace/ForegroundWorkspace.h/.cpp`，负责浮窗注册、前台窗口、交互会话、窗口状态与屏幕边界；`StageStrip.h/.cpp` 负责左侧卡片布局、缓存预览和恢复点击；`WindowTransition.h/.cpp` 负责窗口与卡片间可中断的过渡。首个应用仅 Chrome，接口允许后续接入其他 UI，不提前实现多应用分组管理。

浏览器视图拆成三层：

1. `BrowserPage`：ClickGUI 中的轻量入口与内嵌容器。
2. `BrowserView`：标签、地址栏、设置菜单、网页绘制及鼠标坐标映射；输入为显示矩形和样式上下文，不再依赖 Panel 的固定位置/宽高。
3. `BrowserWindow`：前台调度容器；调用同一个 BrowserView，提供窗口按钮、拖拽、缩放、最大化和最小化。

`BrowserService` 保持独立 CEF/IPC 服务职责，不管理 ImGui 窗口。单个服务同一帧只能由一个 BrowserView 消费：内嵌与浮窗互斥，避免 Visible、Viewport、Focus 和纹理更新相互覆盖。保留统一实例访问，避免不同 Instance 工厂意外创建重复对象。

`ForegroundWorkspace` 不引用 Minecraft/CS2。宿主只接收共享输入意图，例如 `HasInteractiveOverlay()`、`KeyboardOwner()`、`WantsPointerCapture()`，并提供光标/游戏输入适配。展示状态和焦点状态分别记录；宿主窗口线程读取原子快照，不能直接访问渲染线程的 ImGui 对象。

## 当前需要解除的耦合

- `ClickGui::Render()` 关闭时提前返回并调用 Browser Hide：改为共享 UI 帧入口继续渲染前台窗口，Panel 的开关只控制 Panel。
- `ClickGui::SetOpen(false)` 直接隐藏 CEF：由唯一的浏览器展示拥有者决定 Visible，分离动作不能先把浮窗隐藏。
- `PageLayout::content()` 切页会调用 Hide：只隐藏内嵌容器，不影响独立窗口。
- `BrowserPage::Draw()` 固定 570×556、依赖 PanelClickGui：提取矩形驱动的 BrowserView，传入共享主题和缩放上下文。
- 宿主使用 `IsOpen()` 判断网页输入、鼠标捕获：改为组合判断 ClickGUI 与前台交互焦点，覆盖 Minecraft 和 CS2。
- `browserCapture` 当前以整页为粒度：改为由共享输入调度决定。只在浏览器交互期间拦截模块按下，保留配对释放和熔断优先级。

## 渲染、模糊与缩放

默认顺序为 HUD → ClickGUI → 前台浮窗 → 左侧调度栏 → 当前浮窗子菜单；侧栏不截获子菜单输入，不覆盖其他应用的 Windows 窗口。子菜单始终关联父浮窗，移动/收纳时关闭或同步，不能残留在原位置。

复用 Panel 字体、主题、控件动画和现有 BrowserBackdrop。浮窗设置、标签菜单和右键菜单按实际网页矩形采样模糊，不能沿用内嵌坐标。弹窗出现/退场时各帧都保留正确采样引用。

CEF Viewport 尺寸更新合并到每个渲染帧最多一次，拖动仅变位置时不发 Resize。缩放过程中显示最新可用帧；输入统一按实际显示矩形映射到最后一张有效网页帧，防止画面尺寸更新前点击错位。当前最大纹理 1920×1080，超过后等比降采样并保证输入比例一致。

保留现有 OpenGL/DX11/Vulkan 纹理生命周期与 F11 恢复路径；浮窗增加的尺寸变化沿用退休纹理回收，不能每帧积累资源。位置使用逻辑坐标保存，显示时按 DPI/GUI 比例换算，网页缩放和窗口尺寸互不混淆。

## 持久化与状态

浏览器独立设置中增加窗口矩形和上次还原矩形；侧栏位置统一固定在左侧，由调度器布局。矩形按视口比例保存并附带逻辑尺寸限制，分辨率改变时重新夹紧，至少标题栏和控制按钮可见。

运行时布局状态为 `Embedded / Foreground / Shelved`，焦点另存为 `None / Panel / Browser`，过渡动画记录源矩形、目标矩形和当前进度。首次注入使用 Embedded，用户主动进入 Chrome 才启动；不因读取上次浮窗位置就在游戏启动时抢占焦点。CEF 服务故障显示现有重试入口，不丢窗口布局。

## 实施与验收

1. 提取 BrowserView，保持现有内嵌行为，通过浏览器预览回归。
2. 实现 ForegroundWorkspace、BrowserWindow、StageStrip、窗口收纳/恢复动画、分离/停靠和尺寸持久化。
3. 接入两个游戏宿主的焦点与鼠标恢复，保留自定义熔断键。
4. 验证主题/缩放、浮窗移动和网页交互、模糊弹窗、纹理重建与卸载。

验收重点：分离/停靠 URL、历史、登录态、视频进度不重置；所有边角缩放后点击准确；最小化不抢输入；关闭 ClickGUI 不意外隐藏浮窗；ESC 不穿透游戏；按住 W 或鼠标时切换不留下卡键；F11 和分辨率变更后可恢复；熔断清理浮窗、CEF 和纹理资源。

侧栏验收：单个 Chrome 只出现一张收纳卡片；点击恢复保持原尺寸与位置；快速往返动画连续；鼠标锁定时不能误激活；分辨率降低后预览不越界；后台无持续网页帧发布；缓存纹理在收纳和设备重建后不会失效。

本设计不解决 CEF 的 H.264/AAC 缺失；独立窗口与视频解码是两个独立能力，播放器编码兼容需单独完成。
