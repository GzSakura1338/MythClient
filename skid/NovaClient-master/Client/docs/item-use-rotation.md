# 现代版本物品使用与转头一致性

Grim `BadPacketsJ` 核对 1.21+ USE_ITEM 包中的 yaw/pitch：同一 tick 内的使用角度必须一致，且与 tick 的移动角度相同。这是精确浮点比较，不能把相差 360 度视为相同。

Lunar 1.21.11 的 `class_636.method_41929` 在原版预测之前构造 USE_ITEM，直接读取玩家 yaw/pitch；即使冷却或物品逻辑返回 PASS，也可能发包。不能根据使用返回值提前解除保护。

实现位于现有 `RotationManager`，无需逐个增加模块互斥名单：

- 现代 GameTick 入口开始事务，自动物品使用在原版预测之前预约。
- 所有 `GameItemUse::UseStack` 调用共享预约；同步调用期间玩家角度与管理器一致，退出恢复摄像机角度。
- 原版 controller 的 useYaw/usePitch 钩子记录两轴快照，原生玩家输入也走相同的角度来源。
- 同 tick 的第二次自动物品使用延后，自动使用或独占转头期间的原版新右键暂缓。
- 物品射线、移动修复和移动包共用已提交角度。模块结束、平滑回正或后来提交的转头不能覆盖它。
- 移动上报之后不启动新的自动物品使用，避免 USE_ITEM 落在移动包与 tick 结束包之间而引用下一轮角度。
- 方块交互不携带 yaw/pitch，保留原有放置时机；已有自动物品操作时才暂缓，避免与桶/烟花串用。
- 1.8/1.7 与 Forge 1.20.1 不启用此事务。保留原有无界 yaw、整圈摄像机重定位和手部插值处理。

AutoMLG、AutoCharge、ElytraFly 在切槽及推进状态机前检查预约；共享使用入口还会再次检查。AutoCharge 的输入抑制调整至所有交互回调之后执行（事件优先级数值越小越先执行）。

验证：转头实际实现的原生回归覆盖整圈 yaw、使用后释放/回正、竞争使用、手动使用、移动前后边界及重生；Lunar class 重写检查验证新增原生钩子签名和目标调用。服务器实际组合效果需自行注入测试，测试通过不代表保证无 VL。
