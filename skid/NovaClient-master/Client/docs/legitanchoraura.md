# LegitAnchorAura

Combat 分类的持续自动重生锚模块，支持 Lunar 1.21.11 和 Minecraft 26.3。使用原生 C++/JNI，无新增 Java。参数布局参考 LegitCrystalAura。

## 使用

快捷栏准备重生锚、萤石及至少一个非萤石槽位（空槽也可）。副手不要持有萤石，否则普通未充满的锚会走原版副手充能分支，模块不会误将其作为引爆动作。

开启后自动选位，按“放锚 → 读取锚状态 → 充能一次 → 读取充能状态 → 引爆 → 读取消失状态”循环。已有充能锚无需锚物品或萤石即可引爆；未充能锚只需萤石和引爆槽。默认每 tick 最多一次交互，0 ms 不等于同 tick 连发。

| 设置 | 默认 | 说明 |
|---|---|---|
| Target → Range / FOV | 4.5 / 180° | 实际范围同时受原版方块交互距离限制 |
| Target → Through Walls | 关 | 忽略世界方块遮挡，仍检查距离和当前射线命中 |
| Place | 开 | 自动放新锚；关闭后仍能处理已有锚 |
| Prefer Behind | 关 | 优先在目标朝向的正后方放新锚；无有效后方位置时回退正常选位 |
| SafeAnchor | 关 | 在锚靠近自身的一侧补萤石遮挡；确认遮挡并复检自身伤害后才充能/引爆 |
| Place → Delay | 0 ms | 连续新放锚最小间隔，0–1000，步长 5 |
| Place → Auto Switch | 开 | 全流程自动切槽；关闭时按当前手持物品执行当前阶段 |
| Place → Silent | 关 | 全流程复用槽位 spoof，本地手持显示不跟随自动切换 |
| Detonate | 开 | 自动充能和引爆；关闭时仅放锚 |
| Detonate → Delay | 0 ms | 连续引爆最小间隔；引爆冷却期间也不提前充能，0–1000，步长 5 |
| Swing | 开 | 本地挥手；关闭仍发送必要的挥手包 |
| Rotation → Speed | 45°/tick | 1–180，静默平滑转头与移动修复 |
| Safety → Ignore Self Damage | 关 | 跳过自身伤害限制，队友保护保留 |
| Safety → Min Target Damage | 4 | 最小目标伤害 |
| Safety → Max Self Damage | 6 | 自身及队友最大伤害 |
| Safety → Min Remaining Health | 4 | 自身及队友剩余生命与吸收值合计下限 |
| Place ESP | 开 | 复用水晶的 ImGui 方块 ESP 与主题配色 |

## 与 Mio 的选位对应

参考 `AnchorAura.getAnchorAuraData2872/getAutoCrystalData_22873/is2874`、`AnchorAuraData.getAnchorAuraData2056`、`PhaseESPSearchHelper4_2.is3040`。

- 使用 Mio 的 x/y/z 遍历顺序与 floor/ceil 偏移范围，以玩家眼睛到候选方块中心的距离筛选。
- 同时检查已有锚与新放位置。发现第一个安全、可交互且材料能执行的已有锚，立即优先处理；不是将所有已有锚与新位置混成一个总分比较。
- 新放位置完成这一轮分批扫描后，以最高目标伤害选取。每个候选遍历合法玩家，记录满足最低伤害的最高伤害对象；保留本项目 Teams、AntiBot、FOV 筛选。
- 检查可替换方块、世界高度、实际世界边界与放置占位。掉落物、经验球、经验瓶、物品展示框和箭按 Mio 忽略，其他实体阻止放置。液体放置、空气放置不启用。
- 已有效的锚优先完成，失效后重新搜索。已有新放计划的伤害提升不足 0.5 时不切换，减少细微选位抖动。
- 自身伤害和队友伤害是硬限制；不搬入 Mio 对可致命目标放宽自伤的分支。

为对齐 Mio AnchorAura 本身，当前选位伤害使用玩家当前包围盒，不额外套用水晶的未来运动伤害评分。移动时重新检测距离、射线、占位和伤害，不冻结旧世界结果。设计草案中的锚移动外推未启用。

`Prefer Behind` 是可选的选位偏好：以目标当前 yaw 的反方向为后方，在后方左右各 45° 内寻找合法位置。优先接近正后方，方向接近时按伤害排序；仍要求可放置、可交互、满足最低目标伤害和自身/队友安全限制。独立保留正常最高伤害候选，后方位置不存在或复检失效时自动回退；朝向读取失败也回退。已有锚及已提交的充能/引爆流程不受新放位置偏好打断。关闭开关时恢复原有伤害优先选位。

## SafeAnchor

快捷栏准备萤石方块（不是萤石粉）。新的一轮通常需要两块：一块放成遮挡，一块用于充能；已有遮挡或已充能锚按实际需要消耗。位置取锚同高度、靠近玩家的一侧相邻格，优先更贴近玩家与锚连线的方向；无法合法放置遮挡时不退回无防护引爆。

流程为放锚、放遮挡、确认萤石存在、充能、引爆。已有锚也必须先满足遮挡条件。规划阶段只在伤害采样中加入虚拟萤石立方体，不修改世界；对目标、自身及队友都计算遮挡后的伤害，避免只降低自身预测值。遮挡实际存在后改用真实世界碰撞射线复检。SafeAnchor 开启时强制执行 Max Self Damage / Min Remaining Health，自身 Ignore Self Damage 不覆盖这项保护；关闭 SafeAnchor 后维持原有语义。

萤石使用普通可交互支撑面，明确排除任何重生锚，避免将“放遮挡”误执行为“给锚充能”。遮挡放置沿用 Place Delay、Silent、Swing、转头速度及单 tick 交互限制，ESP 在该阶段显示萤石位置。提交后等待客户端状态，失败超时会冷却重算。玩家换边、遮挡消失、材料不足或实际伤害复检失败时不会继续引爆。关闭 Detonate 时仍会放锚及补遮挡，随后停止充能和引爆。

萤石遮挡只能降低部分几何条件下的爆炸伤害，不是免伤保证。客户端状态可能含本地预测，服务端放置失败、其他爆炸以及引爆后的移动和网络变化仍可能影响实际伤害。

## 原版机制与交互

已通过 Recaf 阅读两个版本的 RespawnAnchorBlock。现代版本通过 `EnvironmentAttributes.RESPAWN_ANCHOR_WORKS` 在位置上取值；没有继续调用 Mio 旧版的 `DimensionType.respawnAnchorWorks()`。本地位置允许正常使用锚时停止并提示；每个候选及提交前也单独检查该位置属性。

爆炸强度 5、伤害半径 10、中心为方块中心。复用支持 power 参数的原生伤害公式，水晶仍使用原默认强度 6。曝光射线使用碰撞形状（Collision），而非用于选中方块的轮廓形状（Outline）。采样将终点截在锚方块外侧，只忽略原版爆炸前已移除的锚，不更改游戏世界、不穿过其他遮挡。原版邻水保护修改的是方块爆炸抗性；不将其错误当成玩家伤害缩放。护甲、韧性、难度、抗性与保护附魔沿用原生读取。

读取 CHARGE，只有 0 才充能；大于 0 直接寻求引爆。非萤石主手让原版走 useWithoutItem；副手萤石会提前返回 PASS，因此引爆槽筛选显式拒绝这种双手组合。蹲下会改变方块交互，模块在蹲下时暂停。动作使用原版控制器及共享事务，不构造同 tick 多次使用序列。

提交后最多等待 300 ms 观察客户端世界中的目标状态；这可能包含客户端预测，不等于独立的服务端确认。已进入原生调用但结果不明也等待，超时重新检查并对失败位置冷却 500 ms。不会照搬 Mio 的本地强制设 AIR 或方块更新回调内立即交互。

连续动作保持切槽会话，阶段之间只换所需槽位，结束恢复原槽。手动滚轮不被旧恢复覆盖；原物品身份变化、换世界、同步失败、其他模块持有槽位均沿用所有权约束。

## 模块协调及预算

Anchor 在 GameTick 优先级 0 提供候选，Crystal 在优先级 1 比较有效伤害，Anchor 在优先级 2 根据结果申请独占转头。确认中的操作优先；普通候选伤害相等时水晶优先。模块取得转头后 KillAura 暂停自身转头、攻击和相关疾跑干预。自救、Scaffold、物品使用冲突及网络延迟模块仍优先。

准备与提交共享转头，一 tick 一次平滑步进；提交时检查当前实际射线。保留重复大幅转头变化保护，必要时在同一合法面内选择另一命中点。未获调度的锚不切槽、不交互。

搜索每 tick 最多访问 128 格、评估 8 个候选与目标组合，并在候选/目标之间检查 2 ms 软预算。多目标扫描进度跨 tick 保留，同 tick 的伤害按位置和实体缓存。旧计划、候选收尾及提交复检另计；单次 JNI 调用无法中途打断，队友保护查询不能按数量截断。水晶保留自己的预算，当前不是两模块共用硬性总时间上限，不承诺总耗时低于 2 ms。

普通移动不再因超过 0.75 格而清空未完成扫描。走出原扫描范围或修改 Range 时重建，其余情况继续扫描，并按当前位置复检；每轮结束后重新生成候选网格。槽位查找在同 tick 缓存，原生提交仍独立复查物品。

## 不放置诊断

`nova-base.log` 中 `Anchor:` 每秒最多记录一次当前阶段、扫描进度和拒绝原因计数。`rotation-history` / `ray-wait` 表示尚未满足转头历史或实际射线要求；`interaction-busy` 表示环境或共享交互条件阻止提交；`equip` 表示切槽失败。进入原生提交后，`Anchor native:` 进一步区分动作复检、JNI 命中对象、切槽同步、共享事务和原版控制器返回结果，同样限频一秒。`entered=1` 不代表服务端已确认放置。

## KillAura 交接和放置节奏修复

- 放置/引爆延迟、共享交互可用性及切槽检查提前到取得独占转头之前；条件不满足时不会先让 KillAura 停手。
- 服务器状态尚未确认时保持确认信息及必要的爆炸模块仲裁，但不继续占转头，恢复原武器供 KillAura 使用。新的用物品动作仍须等待确认或原有超时处理，不重复发送。
- 每次连续瞄准最多六个 tick；仍未通过射线或转头历史检查时释放转头、攻击及物品槽，至少让出下一个完整 tick。日志阶段为 `aim-timeout` / `aura-yield`。没有取消射线、伤害、安全或重复放置检查。
- 转头使用配置 Speed 的线性步进上限，去掉距离大于一度时额外减半的收敛，默认速度下更快到位。
- 搜索仍遵循完整伤害排序及已有锚优先；每个搜索片段只读取一次候选玩家ID，每 tick 上限为256个位置、24次目标伤害计算，并保留约2ms预算。没有用首个低伤害新位置替代最终最优选择。

`Client/test/combat/legitanchoraura/run.ps1` 新增确认等待、引爆延迟、长时间射线未到位及外部槽位占用的交接测试；原有循环、SafeAnchor、Mio排序、现有锚、库存和确认测试均通过。低转头速度配合大角度时会周期性让路，而不是长时间独占瞄准。实际服务器中的节奏仍需重新注入验证。

锚回归直接编译生产模块，使用模拟世界和原生边界，覆盖完整循环、已有锚优先、新位置伤害排序、普通/Silent 恢复、手动切槽、禁用、换世界、超时不重复、缺物品、穿墙、慢速转头、自伤/队友保护、Swing、Delay、关闭 Auto Switch 后手动推进各阶段，以及与水晶候选的调度互斥。另覆盖五种初始朝向下启用灵敏度量化的完整循环，以及慢查询和持续移动下扫描不被反复清空。映射测试校验两个实际 jar 的 38 个 JNI 绑定。

后方偏好回归覆盖默认关闭、较低伤害的合法后方优先、目标转身、yaw 跨圈、遮挡/自身危险/目标伤害不足时回退、读取朝向失败，以及已有锚正常引爆。

SafeAnchor 回归覆盖普通/Silent 完整遮挡循环、虚拟立方体曝光采样、材料不足、无独立支撑面、遮挡无效时拒绝 Ignore Self Damage 绕过、放置未确认、仅放置模式、遮挡被破坏及玩家换边后禁止直接引爆。

构建与模拟不能代替实机或服务器验证；服务端规则、网络延迟、其他伤害和目标后续移动会影响实际结果。
