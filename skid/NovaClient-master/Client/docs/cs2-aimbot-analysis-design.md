# CS2 Aimbot：IDA 分析与模块设计报告

日期：2026-09-22。本文保留设计时的分析与待验证项。2026-09-23 已据此实现原生 Aimbot；新增 ABI 核对、最终行为与验证边界见 [实施说明](cs2-aimbot-implementation.md)。未注入或修改运行中的 CS2。

## 1. 结论

建议实现一个可见转头、按住绑定键工作的 Aimbot，使用角度范围筛选、真实模型瞄准点和时间驱动的线性转头。复用现有模块管理、配置、绑定、Team 策略和输入 Hook，并与 Recoil Control 在同一个输入处理链中合成一次最终角度。

现有基础能够支持该方向，但还不能把“找到候选地址”理解为“所有游戏接口已经可直接调用”。本次确认了输入提交、骨骼名称查找、Hitbox 变换和碰撞查询调用链；瞄准点完整布局、射击起点调用契约、Trace ABI 和线程时序仍须在实施阶段验证。烟雾检测仅找到 RTTI 线索，尚未确认完整调用接口。

第一版建议只处理当前可见目标，不增加自动开火、穿墙伤害计算、历史回溯或 Silent 模式。以上是设计范围，不是用户已指定的额外要求。模块不能承诺命中率或任何反作弊兼容性。

## 3. IDA 分析结果

### 3.1 视角输入：复用最终输入提交点

| RVA | 本轮观察 |
| --- | --- |
| `0xB38A40` | 输入处理函数；访问样本计数、样本数组及样本末端角度，在同一函数内两次调用 `0xBA3E20` |
| `0xB38DE1` | 较早的提交调用点，角度来自临时变量 |
| `0xB38E96` | 后面的提交调用点，参数为当前样本 `+0x430`；返回地址 `0xB38E9B` |
| `0xBA3E20` | 通过 slot 查找本地 Pawn，再调用 `0xAD9970` |
| `0xAD9970` | 将 Pawn `+0x12C0` 的旧角度复制到 `+0x12CC`，再写入传入的 12 字节角度 |

反编译中样本步长为 1088，即 `0x440`。这与当前 `sdk/weapons/Offsets.h` 的 sampleStride、sampleAngle 和 commitReturn 一致。

当前 `hooks/InputHook.cpp` 已过滤返回地址与 slot，并验证传入角度指针属于当前样本。因此应扩展这个输入处理链，不能再为 Aimbot 在同一地址装第二个独立 Hook，也不能在 Present 中每帧写 Pawn 角度。

重要限制：新增骨骼和 Trace 调用是否适合这个具体输入阶段，尚未由本轮静态分析完全证明。要先核对原版调用线程和动画更新阶段，再选择在该点采样，或消费同一游戏线程更早阶段发布的有时间戳快照。

### 3.2 玩家目标：现有 ESP 提供身份校验，未提供瞄准点

当前 `sdk/players/PlayerSnapshot.cpp` 已有 controller → Pawn 解析、完整句柄序号、身份回链、重复 Pawn 排除、生命/休眠检查和采集后再次校验。

但 `players::Snapshot` 主要是渲染矩阵、包围盒、名称、血量和队伍。它没有射击起点、命中框、骨骼时间戳、免疫状态或射线结果。不能直接将 Present 采集的 ESP 快照当作输入线程的 Aimbot 目标数据。

建议抽出通用实体身份解析，分别产出渲染快照与瞄准快照。Aimbot 只长期保留“会话代号 + 完整 Pawn 句柄”，不保留裸 Pawn、骨骼数组或命中框指针。

### 3.3 骨骼与 Hitbox：不能把名字查找当坐标读取

| RVA | 本轮观察 | 对设计的影响 |
| --- | --- | --- |
| `0x928330` | 从实体 `+0x330` 取 SceneNode，经虚函数取得对象，转到 `0xA7C970` | 不是直接返回世界位置 |
| `0xA7C970` | 对名称做 hash，再查询模型；模型缺失时返回 `0xFFFFFFFF` | 应作为骨骼查找链处理，须检查无效索引 |
| `0x16571D0` | 转到模型内查找表 `+0x130` 的查询入口 | 进一步支持“名称/编号查找”判断，自动 prototype 遗漏参数 |
| `0x916570` | 查找模型相关对象，查询指定 Hitbox 集合并返回首个结果，含临时容器清理 | 可作 Hitbox set 候选入口，但对象及输出布局仍需核对 |
| `0xA71FC0` | 含 `CSkeletonInstance::GetTransformsForHitboxList` 断言；检查模型初始化，调用 `0xA628A0(a1, 256)`，生成变换列表 | 是有更新和分配行为的接口，不是无副作用 memcpy |
| `0xC143B0` | 原生代码使用 `head_0`、`spine_3`、`pelvis` 等名称建立数据 | 证明名称存在，不证明所有模型固定骨骼编号相同 |

`0xA71FC0` 中读取 `a1+0x1C0` 的变换数据，按 32 字节步长访问；输出也按 32 字节步长生成。它不能被当作传统 48 字节 Matrix3x4 数组。32 字节内容的完整类型、旋转/缩放约定以及 Hitbox 局部中心到世界空间的变换仍需核实。

推荐以模型 Hitbox 语义选择 Head / Chest / Pelvis，使用对应变换计算命中框中心。禁止用 ESP 包围盒顶部、固定高度偏移或固定骨骼编号替代。模型未初始化、点位无效或数据过期时跳过该目标，不自动退回错误坐标。

### 3.4 射击起点：存在时间相关的原生历史

通过字符串 `GetInterpolatedShootPosition time` 的交叉引用定位到 `0x8DB770`。

该函数读取 tick 与 fraction，调用 `0x8DBC50` 查找两条历史记录并对三维位置插值；找不到历史时走服务虚表 `+0x100` 的回退。日志明确提到 weapon services 的射击位置历史。

这说明射击起点不能简单设成“SceneNode origin + 固定眼高”。Schema 中 `m_vecViewOffset` 的类型也是 `CNetworkViewOffsetVector`，不能未经布局检查直接当普通 Vector 读 12 字节。

实施前需确认 `0x8DB770` 的对象、输出参数、时间结构及正确时间来源，并核实当前输入阶段应使用插值射击起点还是服务的当前起点。第一版不借此引入历史回溯瞄准。

### 3.5 可见性：Trace 的布尔返回值不是 visible

| RVA | 本轮观察 |
| --- | --- |
| `0x800FB0` | 构造形状相关参数，转发至 `0x9E6990` |
| `0x9E6990` | 在栈上构造 CTraceFilter，初始化忽略实体等状态，再调用 `0x9E6500` |
| `0x9E6500` | 调用 TraceShape 并合并后续碰撞结果，存在 192 字节结果复制、命中对象和 fraction 比较 |
| `0x9E6040` | 有 `Physics/TraceShape (Client)` 计数器；初始化结果、调用物理查询、处理过滤器 |
| `0x165F310` | 初始化 trace 结果，`+0xAC` 写入 1.0，`+0x08` 置零，设置默认 hitbox 等字段 |

`0x9E6040` 的返回条件为结果 `+0xAC < 1.0` 或 `+0xBB` 状态字节非零。因此 true 不能直接解释成“目标可见”。`0x9E6500` 将结果 `+0x08` 交给实体过滤回调，支持其为命中实体相关字段的判断；完整结果类型仍需从调用点和汇编验证。

建议 Visibility 查询返回三态：Visible / Blocked / Unknown。只有 Visible 可以驱动瞄准。必须区分命中目标、命中其他实体、墙面阻挡、起点位于碰撞体内和查询失败。不能只检查返回 bool，也不能仅凭 `fraction > 0.97` 把远处贴墙目标认定为可见。

不要把 `m_bSpotted` 或 spotted mask 当视线判断；本项目 Radar ESP 改变的是雷达呈现，不能反向作为 Aimbot 的可见性依据。

Trace filter 的内存布局、形状、mask、忽略本地实体和输出对齐都必须使用本版本契约。反编译中存在将 64 位地址标成 int 的类型错误；正式实现前须查看汇编参数，禁止按该 prototype 强转调用。

### 3.6 烟雾、闪光与免疫

本轮字符串搜索找到 `SmokeVolume::GetSmokeDensityInLine`、`GetSmokeDensityLOS` 相关 lambda RTTI，尚未定位成经过验证的可调用入口。普通几何射线未被证明会判断烟雾遮挡；第一版不能把“可见目标”描述成已自动排除烟雾。

以下仅为当前 Schema 记录，实施仍需核对实际语义及读值：

| 字段 | 偏移 | 用途/限制 |
| --- | --- | --- |
| C_CSPlayerPawn::m_bGunGameImmunity | `0x3268` | 候选免疫过滤；不同模式语义需验证 |
| m_flFlashOverlayAlpha | `0x141C` | 闪光状态候选；尚未确定阻止瞄准的阈值 |
| m_flFlashDuration | `0x1428` | 不能仅因数值非零就认定当前仍致盲 |
| C_BaseModelEntity::m_vecViewOffset | `0xE78` | 包装类型，不是已验证的简单 Vector |
| CSkeletonInstance::m_modelState | `0x140` | 模型状态入口，不能等同于最终骨骼数组 |
| CSkeletonInstance::m_nHitboxSet | `0x3FC` | Hitbox set 选择依据 |

Smoke Check 作为后续独立验证项；在验证完成前不要显示一个实际无效的开关。Flash/Immunity 验证完成后可作为内置过滤，避免堆砌第一版参数。

## 4. 建议的模块行为

入口为 Combat → General → Aimbot，默认关闭，绑定默认 Hold、键位默认未设置，由用户选择。按住时辅助，松开立即停止；不主动将视角拉回开启前位置。

| 参数 | 设计初值 | 行为 |
| --- | --- | --- |
| Aim FOV | 5°，范围 1–30° | 以当前方向为中心的最大角距离，即半角，不是整圆直径 |
| Horizontal Speed | 120°/s，范围 0–720°/s | 水平线性转速上限，0 禁用该轴 |
| Vertical Speed | 90°/s，范围 0–720°/s | 垂直线性转速上限，0 禁用该轴 |
| Target | Single / Switch，默认 Single | Single 保持有效目标；Switch 按角距离选择，并设置内部迟滞避免抖动 |
| Aim Point | Head / Chest / Pelvis，默认 Chest | 使用真实命中框中心，无效时跳过 |

这些是便于测试的设计初值，不是已验证的最佳参数。默认限定几何无遮挡目标、有效枪械、本地存活且有弹药。仍由用户开火；不额外模拟鼠标点击。R8、连发和换弹状态复用武器适配，不能只用左键是否按下代表实际射击状态。

Team 统一管理队友筛选，不在 Aimbot 内再增加 Team 开关。但 `Team::ShouldIgnore()` 当前读取 UI 生命周期状态，不能在输入线程直接读取普通 property 或 running_；由 UI 发布不可变队友策略快照，游戏线程复用 `Team::SameTeam()` 的纯判断。

没有目标、目标死亡/遮挡/出范围、模型失效、换世界、失焦、打开菜单或释放绑定时停止辅助并清理锁定状态。Single 在目标失效后可重新获取，不设置额外的强制等待 tick。

## 5. 角度处理与现有功能共存

### 5.1 一次输入，一次最终写入

建议输入链：

`原版输入样本 → 统一快照/设置 → 目标筛选 → 目标点与可见性 → Aimbot/RCS 合成 → 角度规范化 → 原版提交`

先抽出独立于 RCS 开关的公共输入上下文。当前 InputHook 的 Apply 在 RCS 未启用时直接返回，Capture 同时承担武器和有效后坐力求值；直接把 Aimbot 塞进现有 RCS enabled 分支，会导致关闭 RCS 时 Aimbot 也不工作。

Aimbot 与 RCS 都要能独立开启。任一适配失败只停用依赖该适配的功能；不因目标骨骼读取失败关闭正常的独立 RCS。线程间只交换设置和带代号的快照，不跨线程操作 Properties 或游戏对象。

### 5.2 瞄准与后坐力只能补偿一次

`0x8DCC80` 本轮反编译可见：取得基础方向，求值 AimPunch，再合成方向。已存在 `sdk/weapons/AimPunch.cpp` 的有效后坐力适配，应继续复用，不能另读旧版 aimPunchAngle 或再固定乘 2。

建议明确两个坐标空间：输入视角、有效射击方向。目标选择可用有效射击方向；RCS 关闭时，第一版 Aimbot 仅对原始视角提供转向，不隐式启用完整压枪。

RCS 开启时，必须让它成为唯一后坐力补偿拥有者：对有效目标，按现有轴强度、Start Bullet 和 Smooth 约定处理目标方向到输入方向的转换，再做限速；不能先从目标角减一次完整 punch，最后再叠加现有 RCS delta。具体采用重构 RCS 为补偿贡献输出还是协调器提供目标输入，需要在实现前用数值序列测试确定。

目标丢失/松键交还独立 RCS 时要重建基线，避免旧 checkpoint 被当作新目标输入。重复样本不得重复推进锁定、转头或补偿；用会话、frame、sample ordinal、输入时间共同识别，并明确预测重放的恢复规则。

### 5.3 线性速度、FOV 和移动

线性转头每轴步进不超过 `speed * dt`，采用最短 yaw 差并在最终提交前规范化角度。无效/倒退时间重置，长时间暂停后不累计成巨大转头。禁止将每帧固定增量当速度，否则 FPS 改变会改变辅助强度。

Aim FOV 使用三维方向夹角，不能用屏幕像素距离当唯一判断；这样 FOV Control、4:3 拉伸和分辨率变化不会改变筛选角度。未来若显示范围圈，才通过当前投影转换到屏幕。

可见转头会改变玩家的朝向。当前提交点之前已经处理了移动输入；实施时必须检查前进/侧移在最终 yaw 下的语义，避免出现历史 Minecraft Scaffold 那种反向移动现象。不能未经分析就复制其他引擎的 movement fix。

## 6. 建议代码组织

所有新增功能仍使用原生 C++，公共 UI 不包含 CS2 偏移。下面均为拟议路径，本轮未创建这些功能文件。

| 路径 | 职责 |
| --- | --- |
| `src/cs2/modules/combat/aimbot/Aimbot.*` | 属性、Hold 绑定、模块生命周期、设置发布 |
| 同目录 `AimController.*` | 纯算法：目标锁定、Single/Switch、时间限速、重放状态 |
| `src/cs2/sdk/aim/AimSnapshot.*` | 本地射击起点、目标身份、模型点、当前时间快照 |
| 同目录 `Hitboxes.*`、`Visibility.*`、`Offsets.h` | 版本化模型/碰撞适配；偏移集中，边界清楚 |
| 现有 `hooks/InputHook.*` | 唯一原生输入接入与退出排空 |
| `src/cs2/input/AimPipeline.*` | Aimbot 与 RCS 的合成协调，可在实现时按规模决定是否独立成文件 |

不要为了简单直接扩充 ESP 的渲染快照，也不要让 FOV Hook 承担瞄准。FOV Control 只改变世界投影，Aimbot 改输入方向，两者应通过正确坐标空间自然共存。

## 7. 实施顺序与验收门槛

1. 核实射击起点、Hitbox 查询/变换、Trace 入口的汇编 ABI、对象生命周期和线程要求，补齐每个入口的版本/字节校验。验证失败时拒绝启用对应模块。
2. 建立只读瞄准快照与可见性三态，先验证站立、蹲下、跳跃、模型变化和门/墙遮挡，不修改视角。
3. 抽取公共输入处理上下文，保证 RCS 单独启用的既有回归测试不变；再加入纯算法 Aimbot 和统一角度合成。
4. 注册模块、配置、Hold 绑定、ArrayList；复用现有齿轮属性 UI，不新增独立菜单系统。
5. 构建 DLL 并执行独立测试；实际注入与游戏操作由用户完成。

测试至少覆盖：

- 最短 yaw、俯仰限制、零距离点、非有限数值、30/60/144/240 FPS 时间一致性、重复/重放样本。
- 同角目标稳定选择、Single 锁定、Switch 迟滞、遮挡立即失效、实体句柄复用、死亡/复活/切服。
- Head/Chest/Pelvis 点与模型动作一致；不能出现点漂移、蹲下仍瞄准站立头高。
- Trace 命中目标、先撞墙、先撞其他玩家、近墙、起点在碰撞体内、查询失败分别验证。
- Aimbot 单独、RCS 单独、两者共同、进入/失去目标、Start Bullet 和 Smooth 不重复补偿。
- FOV Control 60/90/140、开镜过渡、拉伸分辨率不改变角度筛选；移动输入方向正确。
- Hold 松开、菜单、失焦、卸载和同进程重新注入；回调未排空时不释放跳板。
- 静态 TLS 检查、目录/依赖边界检查及现有完整 NovaCs2Smoke 回归。

性能先限制工作量再测量：基础筛选后只对少数候选求值命中点和射线，锁定目标优先；缓存只在同一有效输入样本内使用。记录查询数量及耗时分位数后再调整预算。本轮未运行性能测试，不给出未经测量的 FPS 损耗数字。
