# AutoBlock 模式

入口：KillAura → AutoBlock 齿轮 → Mode。旧配置默认保留 Lag。

所有模式共用 **Force block animation**（默认开启），独立 AutoBlock 和 KillAura 的 AutoBlock 齿轮中均可设置。开启后，Lag 的格挡/缓冲阶段、Vanilla 的攻击释放与重新格挡周期、Grim 的整个格挡/移动周期，以及 Hypixel 的连续格挡状态都可保持持剑格挡姿态。Hypixel → Lag 原有的 `AlwaysRenderBlocking` 仍是该子模式的附加视觉开关。关闭 Force block animation 后恢复实际使用物品的动画；切换物品、打开游戏界面、退出世界、切换模式或关闭模块会清除强制姿态。这仅影响视觉，不改变攻击、发包、移动减速或 HUD 格挡率统计。

## Vanilla

持剑并找到 Range 内的有效玩家后，用原版使用键开始格挡。攻击请求最多保留一个；达到 Hold ticks 后释放使用键，让 Minecraft.runTick 自己停止使用物品。

后续交互 tick 同时确认本地已经停止使用、释放后已有 C03 移动包通过原有发包入口，才向原版点击队列提交一次攻击与一次右键。runTick 自行执行挥手、攻击、实体交互和使用物品。瞄准方块时不自动右键，避免打开容器等副作用。

保留原版使用物品减速，不启用 Lag 发包缓冲。Force block animation 可在释放攻击期间保持格挡视觉。Velocity 的补攻击在此模式下也提交给同一调度，不直接调用攻击方法。武器不是剑时，普通攻击继续交给原版点击流程。

设置：

- Range：搜索格挡目标的范围。
- Hold ticks：本地确认使用物品后的最短保持 tick 数，1～10，默认 1。达到时间且存在攻击请求时才释放。
- Require right mouse：开启后仅在按住右键时自动格挡，默认关闭。
- Ignore teammates：过滤队友，默认开启。

目标丢失、打开界面、Scaffold 工作、模块关闭或切换模式时清理待攻击状态；退出管理时恢复物理右键状态。

## Lag

保留原先 Raven 对齐的设置与状态机；Lag 参数仅在 Lag 模式显示。切换模式时释放旧缓冲并清理动画和按键状态。

## Grim

使用原版右键建立持剑格挡，等待 Hold ticks 和移动包边界后，先开启出站缓冲，再释放本地使用键。释放包、移动包以及事务确认等后续出站包按原顺序缓存；此阶段本地停止使用物品，恢复正常移动，服务端尚未收到释放包。入站包继续正常处理。

缓冲到期时，确认本地停止使用物品且队列中释放包之后已有移动包，再向原版点击队列提交一次待处理攻击与重新格挡。原版右键流程完成后，连同新产生的攻击、交互和使用包一起按原顺序回放，缩短单独发送释放包后等待重新格挡的空档。多个攻击请求合并为一个，不在回放后批量补打。无法重新格挡或缺少释放后的移动边界时，退回先释放缓冲、再等待边界的路径。

设置仍位于 AutoBlock 齿轮内：

- Hold ticks：建立格挡后的最短保持时间，1～10，默认 1。
- Blink ticks：每次出站缓冲时间，1～6，默认 3；到达对应的 50～300 ms 时间后，在交互阶段结束缓冲。另有额外 100 ms 的异常超时容限和 512 包上限，避免队列因交互未执行而持续积压。
- Release on attack：默认关闭；开启后，有待攻击请求且本地已停止使用物品时提前回放，缩短攻击等待，同时缩短服务端保留格挡的时间。
- Range、Require right mouse、Ignore teammates：与 Vanilla 共用。

目标丢失、切槽、打开界面、Scaffold 工作、关闭模块或切换模式时退出并释放缓冲。收到位置纠正或重生时丢弃旧移动与交互包，只发送缓存的保活、事务确认和释放使用包；断线时丢弃整个队列。随后清理待攻击状态。

正常移动仅发生在本地解除使用物品的阶段；建立和重新格挡仍有原版减速。更长缓冲也会延迟攻击及服务端位置更新，不能据此保证全程无减速、防砍率或零 VL。

建议游戏内先用 Hold ticks = 1、Blink ticks = 3、Release on attack = 关闭、Hit select = 关闭。分别检查移动、攻击节奏、受击、目标离开范围、切槽及关闭模块；需要更快攻击时再开启 Release on attack。本次构建后的注入与游戏内验证由用户执行。

## 验证

### AutoBlockHUD

共用 HUD 拖动标题栏在开关 ClickGUI 时使用约 350 ms 的双阶段动画：打开时先平滑移开内容，再从屏幕所在侧横向展开标题栏；关闭时先收回标题栏，再平滑移回内容。拖动窗口本身尺寸固定，动画不会改写保存的位置。ArrayList、TargetHUD、AutoBlockHUD 共用此行为。

Render → HUD → AutoBlockHUD。齿轮内包含 Animation time、Expand from、Width、背景/文字/进度条颜色与文字阴影；ClickGUI 打开时可预览、拖动并保存位置。模块默认关闭，启用后仅在 AutoBlock 工作及其收起期间显示。卡片以固定透明度横向展开和收起，数字滚动保留；Expand from 可选 Auto、Left、Right，Auto 根据 HUD 所在的屏幕左右半边选择展开起点。关闭 HUD 开关也会完成收起。

百分比表示最近 5 秒内的估算格挡时间占比，刚开始时只计算已经采集的时间。统计观察实际发包入口与 Blink 回放：持剑使用包开始计时，释放使用和切槽包停止计时，缓冲中的包尚不改变状态。开始新一轮 AutoBlock 时重新统计；位置纠正、重生、断线会清空。它不包含服务端确认，不能用作实际挡下攻击比例或减伤率。

纯统计计算可运行 `Client/test/combat/autoblock/run_block_coverage.cmd`；此脚本不连接游戏、不注入 DLL。界面动画和实战效果由用户在游戏内验证。

### Vanilla 状态机

从仓库根目录运行：

```powershell
& Client/test/combat/autoblock/run_autoblock.ps1
```

脚本提取当前 AutoBlock.h / AutoBlock.cpp 编译到模拟环境中，使用依据 1.8 runTick 的输入消费流程和所分析 Grim 检测条件建立的包顺序断言。覆盖 10,000 tick、释放后缺失移动包、物理鼠标点击、右键要求变化、模式切换、目标丢失、非剑武器及界面退出。

这些属于 Vanilla 模式的离线状态机和协议顺序验证，不覆盖新增 Grim 缓冲状态机，也不等于完整 Grim 服务端测试。本次新增模式未运行该脚本或进行游戏内测试。实际减伤、预测偏移、Lunar 的其他功能和服务器插件组合仍需在游戏中验证。
