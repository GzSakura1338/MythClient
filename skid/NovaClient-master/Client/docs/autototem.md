# AutoTotem

Combat → AutoTotem，开启后持续保持副手不死图腾。Delay 为发现副手缺少图腾后的等待时间，默认 0 ms，步长 5 ms。副手已有图腾时不操作；消耗后在游戏 tick 重新读取并补充。

Grim 开关默认关闭，开启后采用短暂输入暂停流程，当前用于具有统一交互事务和现代输入桥的 Lunar 1.21.11 / Minecraft 26.3。其他版本在此模式下不执行换槽；关闭 Grim 保持原流程。

确认有可用图腾后才暂停：取得攻击/使用互斥权，清零方向、跳跃、潜行和 sprint 输入，取消实际疾跑。观察到归零输入之后的 Motion Post 后，下一 tick 重新检查副手、来源槽、界面和光标再交换。交换当 tick 继续暂停，后一个 tick 释放。通常输入暂停约 2 tick（20 TPS 下约 100 ms），不修改速度、击退或发送虚假的静止位置；与服务器确认不是同一概念。

恢复时使用当前物理按键；之前正在疾跑且仍向前按键、没有潜行、界面关闭时，向原版发出一次疾跑按键请求，由原版判断是否能够恢复。Sprint 模块在暂停期间不会重启疾跑。攻击及右键自动化通过共享事务让位。缺物品、其他界面、关闭开关/模块、换世界或输入/运动回调超过 4 tick 未完成时取消暂停，超时后延迟重试。服务器延迟、丢包、缓存发包模块及自定义检查仍需实机验证，不保证绝不触发检测。

参考 OpenMio `module/combat/Offhand.java` 的 Totem 分支和 `do906`：扫描图腾，使用原版菜单 SWAP、button 40，将来源槽与副手交换。快捷栏索引 0–8 转菜单槽 36–44，主背包 9–35 保持原编号。原副手物品回到来源槽，不丢弃、不改变当前选中的快捷栏、不使用鼠标拾取链。

本实现仅移植持续持图腾功能，不含 Mio 的金苹果/水晶副手策略、危险伤害预测、封包线程本地扣减图腾或容器内换槽。JNI 和菜单操作均在游戏线程执行。支持具有副手的现有版本；1.7/1.8 不执行。

打开箱子等其他界面、ClickGUI、FreeCam、鼠标持物及 Refill/ChestStealer 工作时暂停。允许在普通游戏画面或玩家背包内补充。InvManager 在交换当 tick 暂停整理；模块开启期间禁用其副手策略，避免来回交换。关闭 AutoTotem 后副手保留当前物品，InvManager 恢复原策略。

菜单交换后重新读取副手作为本地确认；未确认时至少间隔 250 ms 再试，避免拒绝操作导致连续点击。世界/玩家切换时丢弃旧计时。客户端预测成功不代表服务器最终接受。

验证：`Client/test/combat/autototem/run.ps1` 编译生产模块配模拟 JNI，覆盖来源槽编号、原副手保留、消耗补充、延迟、鼠标持物/容器暂停、失败重试及禁用/旧版。实机注入测试由用户执行。
