**二、相机实现**

推荐采用**独立的相机适配层**，在游戏计算视图的回调里完成工作。UI 线程只发布设置。

每次视图更新：

1. 验证当前为本地存活玩家的正常游戏相机。
2. 保留原版视图计算，取得当前帧的眼睛位置、视角和 FOV。
3. 根据当前视角计算镜头后方的目标位置。
4. 执行相机体积碰撞检测，取得允许的最大距离。
5. 计算距离过渡，输出最终相机位置。
6. 同步本地人物和第一人称手部模型的显示状态。

核心位置关系为：

```text
目标镜头位置 = 本帧眼睛位置 − 当前视角的前方向 × 镜头距离
```

跟随使用当前帧视角，**只对距离做平滑，不延迟鼠标转头**，避免快速转动时镜头拖尾、人物与画面不同步。

最终修改点必须在游戏生成视图矩阵之前，确保现有 2DESP 能使用与画面一致的投影矩阵。

**三、防穿墙与过渡**

镜头碰到障碍物时，立即将距离限制在安全范围；离开障碍物后，再平滑恢复到用户设置的距离。

```text
实际距离 ≤ 本帧碰撞允许距离
```

这个限制在动画计算之后仍要成立。否则，即使碰撞检测正确，平滑动画也可能让镜头暂时留在墙内。

需要单独处理：

- 镜头起点已处于碰撞体内；
- 贴墙转身、墙角和窄门；
- 蹲起、跳跃和落地；
- 传送、复活或切服造成的位置突变。
